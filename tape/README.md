# tape

Tape (colour-under) RF capture test data for the video-decode toolchain.

## Overview

This directory contains vhs-decode / tape-decode-rust test data used to verify
the decode → TBC → export pipeline.

The test data is in FLAC format, the native input format for vhs-decode and
tape-decode-rust. This lets the test procedure run end-to-end: the decoder
turns the `.flac` RF captures into TBC video (and associated metadata), which
is then colour-decoded, dropout-corrected and exported by **tbc-tools**.

Note: Any copyright material is included under fair-use, research. All material
is short clips of a few seconds.

## Repository structure

Tape data is subdivided **by tape format, then by TV system**:

```
tape/
├── vhs/{pal,ntsc,secam,mesecam,palm}/
├── svhs/{pal,ntsc,...}/
├── betamax/{pal,ntsc,...}/
├── quadruplex/{pal,ntsc,secam,...}/
└── scripts/decode_all_test_files.sh
```

For SECAM/MESECAM, the decode uses the 625-line PAL geometry; the SECAM
colourimetry is handled by the chroma decoder (`ld-chroma-decoder -f secam`)
during the tbc-tools stage. Quadruplex SECAM uses the `PAL_QUADRUPLEX`
(625-line) profile.

## Tools

| Tool | Role |
|---|---|
| [vhs-decode](https://github.com/oyvindln/vhs-decode) | Decode colour-under tape RF (VHS/S-VHS/Beta/Quadruplex) → TBC |
| [tape-decode-rust](https://github.com/harrypm/tape-decode-rust) | Rust decode front-end, profile-driven per tape format/system → TBC |
| [FLAC-Chop](https://github.com/harrypm/FLAC-Chop) | Sample-exact cutting of RF-capture FLAC/PCM files |
| [tbc-tools](https://github.com/happycube/ld-decode) | TBC post-processing: `ld-chroma-decoder`, `ld-dropout-correct`, `ld-analyse`, `tbc-video-export` |

### tbc-tools (post-decode TBC processing)

tbc-tools operates on the TBC output produced by the decoders above:

- **ld-chroma-decoder** — colour-decodes the TBC to RGB48 / YUV444P16 / GRAY16.
  Selects the colour standard with `-f` (`pal2d`, `transform2d`, `transform3d`,
  `secam`, `secam-predemod`, `ntsc1d`, `ntsc2d`, `ntsc3d`, `mono`).
  `--full-frame` / `--4fsc` outputs the whole frame without active-area trimming.
- **ld-dropout-correct** — multi-source dropout correction on the TBC.
- **ld-analyse** — GUI viewer / analyser for TBCs (chroma preview, VBI,
  dropout overlay, export dialog).
- **tbc-video-export** — orchestrates dropout-correct + chroma-decode + ffmpeg
  encode into final containers (FFV1/ProRes/AV1 in MKV/MOV/MP4), with proxy
  generation and aspect-ratio/MKV-header normalisation.

## Usage

### Prerequisites
- [vhs-decode](https://github.com/oyvindln/vhs-decode) or
  [tape-decode-rust](https://github.com/harrypm/tape-decode-rust) on your PATH
- [tbc-tools](https://github.com/happycube/ld-decode) built and on your PATH
- Sufficient disk space (TBC files are significantly larger than the FLAC sources)

### Decoding test files

```bash
./scripts/decode_all_test_files.sh
```

This will process the `.flac` files, auto-detect PAL/NTSC from the directory
structure, and write TBC files into the `tbc/` output directory (mirroring the
source structure), producing `.tbc` and `.tbc.db`/`.tbc.json` per input.

### What gets committed vs. generated

The committed, canonical sample is the **RF `.flac`** capture. TBC files
(`.tbc`, `.tbc.json`, `.tbc.db`) and decode `.log`s are regenerated by
decoding and are git-ignored (see `.gitignore`) — do not commit them.

## Test file naming convention

FLAC files follow a descriptive naming pattern:
```
<Title>_<DiscType>_<VideoStandard>_<Side>_<AdditionalInfo>_<Timestamp>_<Position>.flac
```

Examples:
- `SVHS_PAL_EBU_Bars_MISRC_V2.5_40msps_12_bit_16_frames.flac`
- `mesecam_vhs_tape275_testcard_50f.flac`
